# Quick start

## 1. Offline demo with the fake harness

The repository ships a schema-valid fixture set for a micro-course, "Spotting Phishing Emails"
(`tests/fixtures/harness/demo/`, generated by `scripts/gen-demo-fixtures.ts`). With the fake harness every agent
call is answered from these fixtures, so the full pipeline runs without a model or network. One storyboard
reviewer raises a finding in the first cycle, so you also see adjudication, repair and re-review.

Windows PowerShell:

```powershell
$env:COURSEFORGE_HARNESS='fake'; $env:COURSEFORGE_FIXTURES='tests/fixtures/harness/demo'
.\courseforge new "Spotting Phishing Emails" --to release
```

macOS / Linux / Git Bash:

```sh
export COURSEFORGE_HARNESS=fake COURSEFORGE_FIXTURES=tests/fixtures/harness/demo
./courseforge new "Spotting Phishing Emails" --to release
```

What happens:

1. `courses/spotting-phishing-emails/` is created with `course.yaml`, `state.json`, `artifacts.json` and
   `input/concept-request.md`.
2. CONCEPT → INSTRUCTIONAL_DESIGN run and lock (each with a saved execution plan and reviewer panel).
3. STORYBOARD generates two modules, the reviewers find an issue in `M1-F01`, a repair plan is built and
   applied, the reviewer reruns, and the stage **pauses** (exit code 10): STORYBOARD has a `hybrid` gate by
   default.

Inspect and approve:

```sh
./courseforge status --course spotting-phishing-emails
./courseforge findings list --course spotting-phishing-emails --stage storyboard
./courseforge gate approve --course spotting-phishing-emails --stage storyboard
./courseforge continue --course spotting-phishing-emails
```

`continue` runs EDITORIAL through RELEASE: visual direction, the deterministic course model and build, browser
QA with axe and screenshots, and the release gate. If QA leaves blocking findings the run pauses at COURSE_QA;
read `review/consolidated-review.md` and `review/functional-tests.json`, then decide with `findings` and `gate`
commands (see [human-review.md](human-review.md)).

To skip the storyboard pause, pass `--gate auto` to `new`. For a faster QA pass, set
`COURSEFORGE_QA_PROFILE=smoke`.

Open `courses/spotting-phishing-emails/build/index.html` (or `release/course.html` after release) in a browser.

## 2. A real course

```sh
./courseforge doctor                                   # claude.auth or codex.auth should be ready
./courseforge new "Safe Ladder Use" --audience "warehouse staff" --duration 30 --jurisdiction "Ontario, Canada" --to design
```

Stop at a stage, read the output, then continue:

```sh
./courseforge status --course safe-ladder-use
./courseforge run --course safe-ladder-use --to storyboard
./courseforge run --course safe-ladder-use --to release --backend codex
```

Add background material with `--notes <file>` on `new`. Research stages use the agent's web tools. A full course
takes many agent calls; start with a narrow topic.

## 3. One command: give it what you have, come back when it is done

```sh
./courseforge make "Chemical safety data sheets for new warehouse staff" ./our-policies/ --review one-shot
```

`make` accepts a description, documents or folders, or a half-finished course (one `.html` or `.json` file). In a
terminal it asks the setup questions first; choose **Do it all, then ask me once at the end**. It then works
unattended and stops once, when the course is finished and tested, telling you where to look and how to approve.

## 4. Start from something you already have

```sh
./courseforge ingest path/to/storyboard.md --course my-course --stage storyboard --mode improve
./courseforge run --course my-course --to release
```

See [ingestion.md](ingestion.md) for formats, stage inference and modes.
