# ADR 0002: zod as the single source of truth for schemas

## Context

Every artifact, registry and agent output needs a TypeScript type, runtime validation and, for agents, a JSON
Schema (Codex needs a schema file; Claude Code takes it inline). Hand-written parallel schemas drift.

## Decision

zod v4 schemas in `src/core/schemas/` are the only definitions. Types come from `z.infer`. JSON Schemas are
generated by `scripts/gen-schemas.ts` into `schemas/*.schema.json` and committed; `--check` fails on drift.
Agent-facing schemas are flat and strict (every property required, optional values nullable, no `$ref`,
`additionalProperties: false`), produced and linted by `src/core/wire-schema.ts`, because both backends' strict
structured-output modes support only that subset.

## Consequences

- A schema change is one edit plus `npm run gen:schemas`; CI and `doctor` (`schemas.drift`) catch forgotten
  regeneration.
- Agent schemas cannot use optional fields; code treats `null` as absent where needed.
